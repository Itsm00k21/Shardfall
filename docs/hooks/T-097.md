# T-097 hooks for GHOST

`TrainingGrove` is pure. It does not swing, dodge, heal, paint a telegraph, or grant keys or gold. Clearing it flags `grove_ribbon` once. `paid` does not complete a station. A paid skip is refused. Nothing in `src` loads it yet. It does not load `CombatFeel`, `RaidPractice`, or `Codex`.

`hit` counts one finite non-negative hit and adds its damage. One hit finishes the dummy (`dummyHits` is 1), including a hit of 0. The dummy stays up. `heal` adds healing and completes nothing. `readout` takes the elapsed seconds the caller measured and returns damage, healing, dps, and hps. Elapsed 0 yields dps 0 and hps 0. `dodge` completes the course only on `red`. `color` marks one of `red`, `yellow`, `purple`, and `blue`, and the room completes when all four are marked. A red dodge does not mark red. A color mark does not finish the dodge course. `clear` sets the cosmetic flag only when the dummy, the dodge course, and the color room are all done. A later clear of that saved state does not set it again. Store `state` only when `ok == true`. Grant the ribbon only when `granted == true`. Each call returns a new table.

```lua
local opened = TrainingGrove.fresh()
-- opened.state.up == true
-- opened.state.dummy == false
-- opened.state.dodge == false
-- opened.state.room == false
-- opened.state.cosmetic == false

local struck = TrainingGrove.hit(state, {
	damage = damage, -- finite and >= 0, counted on the server
	paid = paid, -- accepted and ignored
})
-- Store struck.state only when struck.ok.
-- struck.counted is true for that one hit. struck.up stays true.
-- struck.dummy is true once hits >= 1. struck.keys == 0 and struck.gold == 0.

local healed = TrainingGrove.heal(state, { healing = healing })
-- healed.dummy, healed.dodge, healed.room, and healed.cosmetic do not flip on.

local shown = TrainingGrove.readout(state, { elapsed = elapsed })
-- shown.dps and shown.hps use elapsed. shown.window == 10.
-- No reward. Do not grant a ribbon from a readout.

local dodged = TrainingGrove.dodge(state, { color = "red" })
-- dodged.completed is true only the call that finishes the course.
-- Yellow, purple, and blue stay ok and leave dodge false.

local marked = TrainingGrove.color(state, { color = "blue" })
-- Pass the color id, not the verb. "interrupt" is refused.
-- marked.room is true only when red, yellow, purple, and blue are all marked.

local cleared = TrainingGrove.clear(state)
-- Store cleared.state only when cleared.ok.
-- When cleared.granted, the new flag is grove_ribbon.
-- cleared.keys == 0 and cleared.gold == 0. cleared.payout is nil.
-- A second clear of cleared.state returns granted == false.
```

The frozen config is:

| field | value |
|---|---|
| `dummyHits` | 1 |
| `staysUp` | true |
| `window` | 10 |
| `colors` | `red`, `yellow`, `purple`, `blue` |
| `dodgeColor` | `red` |
| `cosmeticId` | `grove_ribbon` |
| `keys` | 0 |
| `gold` | 0 |

Those color ids are the same four as `CombatFeel.TELEGRAPHS`. This module does not load that module, and it does not accept the verbs `dodge`, `stack`, `spread`, or `interrupt`.

`grove_course` in `docs/content/quests_side.md` is the quest: one hit, one red dodge, one blue interrupt, 15 gold, 0 keys, and 1 Grove Ribbon. This module does not pay that 15 gold or those keys. The blue interrupt is `color` with `blue`. The ribbon id is `grove_ribbon`.

A `userId`, `UserId`, `playerId`, `PlayerId`, `guildId`, or `GuildId` field refuses the call. The result does not copy that field. A `productId`, `robux`, `cost`, or `skip` field refuses the call and grants nothing, including `robux = 0`, `cost = 0`, and `skip = false`. `paid = true` matches `paid = false` for a real hit, heal, dodge, color, readout, or clear. It does not finish a station the action did not earn. There is no paid skip of the grove.

A non-finite or negative hit is refused, and so is a non-finite or negative heal. An unknown color is refused. A saved record that disagrees with itself is refused: `dummy` must match `hits >= 1`, `room` must match all four marks, `up` must stay true, and `cosmetic` may be true only when all three stations are done. A failed call keeps the previous save.

Suggested server calls, after this merges: the grove dummy on the south edge of the plaza, the red dodge in that course, and each telegraph color the server has already seen the player handle. Build the arguments on the server. Do not forward a client user id, guild id, or state. Do not call this from `RaidPractice`, `CombatFeel`, `Codex`, `Onboarding`, or `OnboardingService`. Do not bump Schema. The grove is not a new Haven district, and it is not Practice Grove.

There is nothing to pay through `Economy`. Do not grant gold or keys from `clear`. The cosmetic flag is the whole reward, and only when `granted == true`.

## Questions

1. The design says clearing the grove gives a small cosmetic. `grove_course` also pays 1 Grove Ribbon, plus 15 gold and 0 keys. This module sets `grove_ribbon` once and pays 0 gold and 0 keys. Suggested: one ribbon, granted only when `granted == true`, and the quest hand-in does not grant a second copy. The 15 gold stays on the quest. If both pay a ribbon, the player gets two for one course. Needs Kevin.
2. `grove_ribbon` is a content row (Common, bound, no stats). It is not a live catalog id. Suggested: store the flag and the id, and do not equip the ribbon until a catalog row exists. Needs Kevin if the ribbon has to show on the character in this pass.
3. `readout` divides the session totals by the caller elapsed. Elapsed 0 yields 0. Elapsed 20 still divides by 20, and `window` stays 10. There is no ring buffer, so damage older than 10 seconds does not fall off. Suggested: keep the session rate, and let the UI label the placeholder as 10 seconds. Needs Kevin if the meter must drop damage outside that window.
4. Who keeps a clear across an alt? `fresh()` starts empty. A saved record is the memory. A second character is a new profile today, so the alt walks the grove again. Suppressing that needs an account flag that does not exist. Needs Kevin, same call as T-088, T-095, and T-096.
5. Where should the record live? It is not in Schema. Schema stays 21. Suggested: add `trainingGrove` on the next free version, `{ hits, damage, healing, up, dummy, dodge, colors: { red, yellow, purple, blue }, room, cosmetic }`. Keep the numbers and the booleans stored. Do not fold this into `codex`, `Onboarding.starter`, `FirstSession`, `StarterGoals`, or a raid field. Nothing in `src` loads this module until that wire. Pass the profile's saved state. Save the returned state only when `ok == true`. A failed call keeps the previous save. Do not apply two clear results that both started from the same old state. `keys` and `gold` stay 0.
6. Where do the calls sit? Suggested: the server calls `hit`, `heal`, `dodge`, and `color` from the plaza grove, then `clear` when the three stations are done, and `readout` when the meter asks. The client paints the numbers and does not call `clear`. A world prop waits for a row that names `Haven.luau`. There is no grove tab. `UiRouter` and `Keybinds` stay as they are. The page does not open itself. There is no `blocked` flag and no required step.
7. Should a red dodge also mark red in the color room? Suggested: no. The course and the room stay separate, so a red dodge does not mark red, and `color` red does not finish the course. The blue interrupt is a `color` call, not a dodge. Pass `red`, `yellow`, `purple`, or `blue`. A verb string is refused.
8. `paid` is ignored, and `productId`, `robux`, `cost`, and `skip` refuse the call. Suggested: keep that split. A real red dodge with `paid = true` still finishes the course and still pays nothing. `paid = true` on an unfinished clear does not set the ribbon. A skip field on a finished clear grants nothing and leaves `cosmetic` false.
