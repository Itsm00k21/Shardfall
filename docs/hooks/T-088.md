# T-088 hooks for GHOST

`FirstSession` is pure pacing. It does not roll, mint a template, hatch an egg, or grant gold. A paid roll and a free roll take the same Rare floor. A paid skip is refused. Nothing in `src` requires it yet.

`applies(state, step, classId?)` says whether that step is still rigged. `meets(step, offer)` compares the caller's offer to the rule and does not record anything. `grant(state, step, offer)` records the step only when it still applies and the offer meets it. `skip(state, request)` records every step that was still open and returns those rules. `rigged(state)` is false for a returning player and after the kit. Store `state` only when `ok == true`. Each call returns a new table.

```lua
local opened = FirstSession.fresh()
-- opened.state.returning == false
-- opened.state.granted.roll == false

local live = FirstSession.applies(state, "roll", classId)
-- live.applies and live.rule.floor == "Rare" and live.rule.orBetter == true

local noted = FirstSession.grant(state, "roll", {
	rarity = rolledRarity, -- the rarity the server actually returned
	element = rolledElement, -- Verdant, Tide, Fire, Frost, or Void
	classId = classId,
	picks = nil, -- or exactly two elements, one of them the class element
	paid = paid, -- accepted and ignored
})
-- Store noted.state only when noted.ok. Mint noted.reward only when noted.accepted.
```

The other steps use the same `grant`. The chest offer is `{ weapon = { kind = "Weapon", rarity, sockets, classId }, egg = { kind = "egg", rarity } }`. The mini-boss offer is `{ kind = "Armor", rarity }`. The Forge offer is `{ kind = "Ring", rarity, cost }` and `cost` must be 0. `skip(state, { classId = classId })` returns the rules for the steps still open. `paid`, a `productId`, a `robux` amount, or a non-zero `cost` refuses the whole skip.

Suggested call sites, after this merges: the first shard roll, the first chest, the Gnarl's Sprout loot, the first Forge craft, and `OnboardingService.skip`. Do not call this from `RollMath`. Do not edit `Onboarding.luau`. Do not bump Schema. This record is not folded into `Onboarding.starter`.

## Questions

1. The class elements live here because `Classes.luau` has no element field. The map is warden Verdant, tidecaller Tide, forgeborn Fire, frostblade Frost, voidcaster Void. Are those the five strings the shard should match?
2. A pick of two is optional. When `picks` is present it must be exactly two known elements, one of them the class element, and the rolled element must be one of those two. With no picks, only the class element matches. Should the pick of two stay, or is the class element the only match?
3. The roll floor is Rare or better. The chest weapon is exactly Rare, with exactly one socket. The egg floor is Uncommon or better. The armor piece and the ring are exactly Uncommon. A higher weapon, armor piece, or ring does not consume the step. Should a higher piece consume it instead?
4. There is no element field on a `RollMath` item. The caller passes `element`. Who maps the rolled shard to Verdant, Tide, Fire, Frost, or Void before `grant`?
5. `ItemBases` kinds are `Weapon`, `Armor`, and `Pet`. There is no `egg` kind and no ring slot. Profile `eggs` is a count. Armor slots are helm, chest, legs, and boots. `Pets.combos` mentions `verdant_ring` only as a combo flag. Which template, slot, and egg species should the server mint from these rules?
6. `skip` requires a class id while the roll or the chest is still open, so the rules can name the class. A skip before the player has a class is refused and grants nothing. Should that wait for the class pedestal, or should skip grant the armor and the ring first?
7. `fresh({ returning = true })` gets nothing, including a skip. This module does not read `onboardDone`. Should an alt, and any profile that already has `onboardDone`, be passed as `returning` so this kit is not granted again?
8. Where should the `{ returning, granted }` record live? It is not in Schema. Schema stays 21. A later wire can add `firstSession` on whichever version is free. Until then nothing in `src` should require this module.
9. `Onboarding.starter` still grants 250 gold, 40 Shard Keys, one Rare chest token, one Uncommon chest token, and 3 healing tonics. These gear rules do not replace that. Should the Rare weapon and the pet egg sit beside those chest tokens, or replace them?
10. The design says the pet egg hatches immediately. This module does not hatch. Should `PetService` hatch the egg the chest rule accepts, or should the player hatch it later?
11. Step order is not enforced. The Forge ring can be recorded before the roll. Should the timeline order be required?
12. A paid roll does not raise the floor and does not add odds. Confirm the Roll screen must not pass a higher floor for a Prism or Robux crack. A paid skip stays refused.

## Answers from Ghost

1. Yes. The five strings are `Verdant`, `Tide`, `Fire`, `Frost`, and `Void`, from `docs/design/shardfall_classes.md` (Fire burn, Frost slow, Void curse, Tide heal-on-hit, Verdant shield-on-hit). Warden is Verdant, Tidecaller is Tide, Forgeborn is Fire, Frostblade is Frost, Voidcaster is Void. Do not match pool shorts. `Sunken` is not `Tide`, and `Ember` is not `Fire`.
2. Keep the pick of two. One pick is the class element, the other is a different known element, and the rolled element is one of those two. With no picks, only the class element matches. Paid and free use the same rule. A paid roll does not get a third pick. `skip` does not take picks: it names the class element only, so a skip is not a way to choose the other element.
3. A higher weapon, armor piece, or ring does not consume the step. The kit is exactly Rare for the weapon (one socket), exactly Uncommon for the armor, and exactly Uncommon for the ring. The egg stays Uncommon or better. The roll stays Rare or better. The wire offers only that kit item. An Epic that came from somewhere else is not this step, and it must not be passed in as the offer. Exact match means a mistaken higher offer cannot eat the tutorial.
4. The server writes `element`. It uses `FirstSession.ELEMENTS[classId]` for the server's class id, or one of the two stored picks. It does not read `RollMath`, a pool `short`, or the client.
5. Mint `noted.reward`, not the raw offer. The loadout already has an accessory slot named `ring` (`Schema.ACCESSORY_SLOTS`). `ItemBases` has no ring row and no Uncommon armor row, and ascension 0 has no Rare hammer for Forgeborn. Do not stand in `living_bark_cuirass` (Rare) for the Uncommon armor, `green_tyrant` (Mythic) for a hammer, or the `verdant_ring` combo string for the ring. Kevin decided on 2026-10-17 to fill those gaps with existing Common catalog gear. Do not add templates, and do not stand a higher rarity in for a missing row. The first pet is not one of these gear rows. It waits on G-078. Kevin rejected a cute pet.
6. Wait for the class pedestal. A skip before the profile has a server class id is refused and grants nothing. Do not grant the armor and the ring first. One skip after the class is chosen closes every step still open, at the floor, for that class.
7. Pass `returning = true` when this profile's `onboardDone` is already true before this session grants anything. Schema version 14 already set that on old saves, so a playtest character does not get this kit. A new profile starts `onboardDone` false and gets the kit once. This module does not read the clock or account age. Kevin decided on 2026-10-17 that an alt starts fresh. A second character is a new profile and gets this kit. Do not add an account flag. An `onboardDone` profile gets none.
8. On the wire, add `firstSession` on the next free schema version: `{ returning: boolean, granted: { roll, chest, miniboss, forge } }`. Schema stays 21 now. Do not fold it into `Onboarding.starter`. Nothing in `src` requires this module until that wire. Build the offer on the server. Pass `profile.classId`, never a client class id. Mint only when `accepted == true` (`meets` alone is not a grant). Save the returned state only when `ok == true`, and only after that mint, in the same mutate. A failed call keeps the previous save.
9. The weapon and the egg sit beside the currency kit. Keep the 250 gold, 40 Shard Keys, the Rare chest token, the Uncommon chest token, and the 3 healing tonics. Do not open those tokens into a second rigged weapon. The tutorial chest is this module's chest, not the token.
10. Hatch immediately, so the pet is already following. Do not call `Pets.hatch`. That roll uses RNG and can land Common through Epic. Kevin decided the first pet is Common, cool and useful, not cute, with one utility perk and an edgy look. Do not mint `mossback`, `tide_sprite`, `moss_hare`, or `acorn_newt`. The species waits on G-078, and the pet slot stays empty until he picks one. Do not hatch a Rare or Epic. Paid and free get the same pet. The pure module still describes an Uncommon-or-better egg. T-124 does not change that rule to sneak a pet in.
11. Order is not required. The timeline is the guided path. Each step grants once, in any order. After all four, `rigged` is false and a later roll is not floored by this module.
12. Confirmed. A Prism crack and a Robux crack use this same Rare floor. Do not pass a higher floor because the roll was paid. `paid` is ignored on `grant`. A paid skip stays refused: `paid`, a `productId`, a `robux` amount, or a non-zero `cost` grants nothing and does not mark the steps. A skip that is allowed mints the floor exactly (Rare class element, Rare weapon with one socket, Uncommon-or-better egg, Uncommon armor, free Uncommon ring). It does not roll the live odds. Nothing here costs Robux.
