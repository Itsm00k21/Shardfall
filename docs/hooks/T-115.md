# T-115 hooks for GHOST

`NameplateTitles` is pure. It does not roll, clear a room, hatch a pet, or paint a name. Unlocking pays nothing: `keys`, `gold`, `marks`, `stats`, and `luck` are 0. `paid` does not unlock a title the counters have not earned, and it does not block one they have. A paid skip is refused. Nothing in `src` loads it yet. It does not load another module, and it does not call `TextService`. That filter is T-114. This is not the premade board title filter.

`unlock(state, progress)` sticks any title whose counters are met. A `true` flag stays true when a later call is short, including `capped_pouch` after `raidMarksEarned` drops to 0. `nameplate(state)` returns the unlocked rows in catalog order. The nameplate text is `name`. Store `state` only when `ok == true`. Each call returns a new table.

```lua
local opened = NameplateTitles.fresh()
-- opened.state.unlocked.soft_step == false

local noted = NameplateTitles.unlock(state, {
	perfectDodges = perfectDodges, -- whole numbers, counted on the server
	rooms = rooms,
	launches = launches,
	cracks = cracks,
	hatches = hatches,
	trades = trades,
	tonics = tonics,
	listings = listings,
	rootvaultNormal = rootvaultNormal,
	skills = skills,
	bonusCracks = bonusCracks,
	storyWings = storyWings,
	party = party,
	logins = logins,
	combos = combos,
	thorns = thorns,
	rootvaultHard = rootvaultHard,
	classes = classes,
	affinity = affinity,
	bond = bond,
	normalWings = normalWings,
	friendClears = friendClears,
	rootvaultNightmare = rootvaultNightmare,
	epicPity = epicPity, -- sinceEpic + 1
	legendPity = legendPity, -- sinceLegendary + 1
	species = species,
	wings = wings,
	itemBases = itemBases,
	sameWing = sameWing,
	raidMarksEarned = raidMarksEarned,
	awakenedNormal = awakenedNormal,
	mythicItems = mythicItems,
	common = common,
	uncommon = uncommon,
	rare = rare,
	epic = epic,
	legendary = legendary,
	mythic = mythic,
	practice = practice, -- true grants nothing new
	paid = paid, -- accepted and ignored
})
-- Store noted.state only when noted.ok.
-- noted.granted lists ids that flipped on this call, in catalog order.
-- noted.titles is every unlocked nameplate: id, name, rarity.
-- noted.keys, noted.gold, noted.marks, noted.stats, and noted.luck are 0.
-- noted.payout is nil. Do not grant a stat, luck, or marks.

local shown = NameplateTitles.nameplate(state)
-- Paint shown.titles. This call does not unlock.
-- The nameplate text is title.name. Do not filter it here.
```

Every progress field is required, and it is a whole number at least 0. `practice` is required and it is a boolean. A missing field, a fraction, NaN, or an unknown field refuses the call and unlocks nothing. The five reserved ids are not fields and they are not title ids: `sidestep`, `reel_light`, `mythic_hand`, `heartwood_student`, `boardwalker`. A saved record that carries one of them is refused.

A `userId`, `UserId`, `playerId`, `PlayerId`, `guildId`, or `GuildId` field refuses the call. The result does not copy that field. A `productId`, `robux`, `cost`, or `skip` field refuses the call and grants nothing, including `robux = 0`, `cost = 0`, and `skip = false`. `paid = true` matches `paid = false` for a real counter. It does not stick a title the counters missed. There is no paid skip of a title.

`practice = true` grants no new title, even when every counter is at its count. Titles that were already stuck stay stuck. Build `progress` on the server. Do not forward a client user id, a guild id, or a friend id. Do not call this from `TrainingGrove`, `RaidService`, or a raid module. Do not bump Schema. The equipped title is not chosen here.

Suggested server calls, after this merges: pass the saved `{ unlocked }` plus the counters the server already stored, on the action that can move one of them. Save the returned state only when `ok == true`. A failed call keeps the previous save. Do not apply two unlock results that both started from the same old state. Paint `nameplate` from the saved state. Do not filter the name in this module.

There is nothing to pay. Do not grant keys, gold, marks, stats, or luck from an unlock.

## Questions

1. Tenth Luck's sentence is one crack while the live x2 luck bonus is the crack being rolled. The name says tenth, and the live bonus is every 10th crack. Suggested: the count is 1, on `bonusCracks`. The server increments it only when that finished crack had the x2 bonus. It is not 10 cracks, and it is not a second pull.
2. Pity Ready and Long Count do not write 100 or 1000 in the unlock cell. The rules table says Epic pity is 100 and Legendary pity is 1000. Live pity arms when `since + 1` reaches that number. Suggested: `epicPity` is `sinceEpic + 1` and unlocks at `>= 100`. `legendPity` is `sinceLegendary + 1` and unlocks at `>= 1000`. Chest pity is not these counters. After the streak resets, the title stays. 99 and 999 do not unlock.
3. Door Four says "a party of 4". That can be exactly 4 or at least 4. Suggested: `party >= 4`. A party of 3 does not unlock. A party of 5 does. Pass the size at entry. A later solo snapshot does not remove the title. The clear is not required.
4. Five Classes is one hit as each of the five classes. Suggested: `classes` is the count of distinct classes with at least one landed hit, and it unlocks at `>= 5`. This module does not copy class ids. The live ids to count are `warden`, `tidecaller`, `forgeborn`, `frostblade`, and `voidcaster`. Any landed hit on that class counts, including a basic attack. Practice Grove hits do not.
5. Gold Ladder is five rarities, not one counter. Suggested: `common`, `uncommon`, `rare`, `epic`, and `legendary` are each `>= 1`. `CONFIG.rung` is 1. The count is 5. Mythic does not fill Legendary. Secret is not a field and fills nothing.
6. "Or better" is not a separate counter in the doc. Suggested: the server passes exact-tier counts, and this module sums them. `rare_chip` is `rare + epic + legendary + mythic >= 1`. `epic_seen` is `epic + legendary + mythic >= 1`. `legend_chip` is `legendary + mythic >= 3`. `mythic_reel` is `mythic >= 1`. A Mythic roll counts toward the lower "or better" titles. Secret does not.
7. Two Depths says the same wing on Story and on Normal. The word "two" can be read as a count of 2. Suggested: `sameWing` is how many wing ids have both a Story clear and a Normal clear, and it unlocks at `>= 1`. Story on one wing and Normal on another stays 0. This module does not derive `storyWings` or `normalWings` from `sameWing`. The server should pass those too when the same wing earned them.
8. Four Wings says any live difficulty. Suggested: `wings >= 4` counts a wing once if the server has a clear on story, normal, hard, or shardbreaker. Fracture is not a difficulty. Guided is not a difficulty. Practice does not count. This module does not copy wing ids. The live ids are `twins`, `sapwell`, `galecrown`, and `awakened`.
9. Awakened Name says Grandmother Gnarl Awakened on Normal. Suggested: `awakenedNormal >= 1` means wing id `awakened` on difficulty `normal` only. Story, Hard, and Shardbreaker do not increment it. Practice does not.
10. Friend Clear needs a Roblox friend, and this module must not take a user id. Suggested: `friendClears >= 1`. The server increments it only after a Normal dungeon clear where it already decided a Roblox friend was in the party. A friend id on the progress table is an unknown field and is refused. Hard, Nightmare, and Practice do not increment it.
11. Capped Pouch says `raidMarksEarned` reaches 600, and a later week reset does not remove it. Suggested: `>= 600` sticks. A later call at 0 keeps the title. 599 does not unlock. This module does not read a week key or a clock. The 200-mark shop title is not this counter.
12. Card Stack says 20 distinct item-base ids at the same time. Suggested: `itemBases` is the current count. The first call at `>= 20` sticks. A later call at 19 keeps the title. This module does not store a high-water mark. The flag is the memory.
13. Prism Name needs one Mythic item and 1000 cracks. Suggested: both on the same call, `cracks >= 1000` and `mythicItems >= 1`. `mythicItems` is how many Mythic items are owned now, not lifetime. If either is short, it does not unlock. After it unlocks, selling the item does not remove it. Owning a Mythic item alone is not this title.
14. Full Garden needs all 8 species and Affinity 5 on one of them. Suggested: `species >= 8` and `affinity >= 5` on the same call. `hatches` is a different counter, so eight hatches of one species do not fill `species`. Bond does not fill affinity. After it unlocks, releasing pets does not remove it.
15. Practice Grove does not count, and the caller passes the counters. Suggested: `practice` is required. `true` grants no new title even when every counter is already at its count. Counters are still validated. Titles that were already stuck stay stuck. The server also leaves grove actions out of the counters, so a later call with `practice = false` does not inherit them.
16. `paid` is easy to read as either ignored or as a block. Suggested: `paid = true` matches `paid = false` when the counters are met, and it does not unlock a short title. `productId`, `robux`, `cost`, and `skip` refuse the call and grant nothing, including `robux = 0`, `cost = 0`, and `skip = false`.
17. The doc gives a hex for each rarity and says the tint is the live rarity color. Suggested: store the rarity name only. Do not copy the hex. Do not return a Color3. The painter uses the live color. This module does not filter `name`.
18. Forty titles can be unlocked, and a nameplate shows one line. Suggested: this module does not choose the equipped title. `nameplate` returns every unlocked name in catalog order. The equipped id is a later wire. Do not fold that into `milestoneTitle`.
19. Morning Seven can be read as a login streak. The live streak resets. Suggested: `logins >= 7` is a lifetime count of claimed daily login chests, not the streak. A missed day does not remove the title.
20. Skill Hand says class skills, and it does not say whether the ultimate counts. Suggested: `skills >= 50` counts class skill casts and the ultimate. It does not count the basic attack or dodge.
21. One Trade says a finished direct trade. A listing is a different title. Suggested: `trades` increments on a completed direct trade. A cancelled trade does not. A Market Board post increments `listings` and does not increment `trades`.
22. Tonic Made and Thorn Made name recipes this module does not store. Suggested: the server counts crafts of `healing_tonic` toward `tonics`, and crafts of `thornbound_blade` toward `thorns`. Those ids stay on the server.
23. Room One is a room. Vault Walker, Deep Vault, and Night Root read like full clears. Suggested: `rooms` is dungeon rooms cleared. `rootvaultNormal`, `rootvaultHard`, and `rootvaultNightmare` are full clears on those difficulties. A room does not increment a clear counter. A clear does not have to increment `rooms` beyond the rooms that were actually cleared.
24. The doc says tutorial saplings count for Tenth Launch and the tutorial crack counts for One Pull. Suggested: the server includes them in `launches` and `cracks`. This module does not subtract them.
25. Where should `{ unlocked }` live? It is not in Schema. Schema stays 21. Suggested: add `nameplateTitles` on the next free version, `{ unlocked: { the forty booleans } }`. Keep the counters derived. Do not fold this into `milestoneTitle`, `codex`, `trainingGrove`, or a raid field. Nothing in `src` loads this module until that wire. Pass the profile's saved state. Save the returned state only when `ok == true`.
26. Combo Spark says one live combo. Suggested: `combos >= 1`. This module does not copy combo ids. The server increments it when a live combo fires.
