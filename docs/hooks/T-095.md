# T-095 hooks for GHOST

`StarterGoals` is pure. It does not craft, clear a dungeon, roll, level a player, or add Shard Keys. `paid` does not change the amount. A paid skip is refused. Nothing in `src` loads it yet.

`show(state, progress)` is the tracker. It returns at most three goals: the first ones not yet granted, in order. `grant(state, goalId, progress)` records one goal and pays only when that goal is in those three, the count meets it, it was not granted before, and the player is not returning. Store `state` only when `ok == true`. Pay only when `accepted == true`. Each call returns a new table.

```lua
local opened = StarterGoals.fresh()
-- opened.state.returning == false
-- opened.state.granted.forge == false

local shown = StarterGoals.show(state, {
	forge = craftCount, -- whole number, counted on the server
	rootvault = clearCount,
	rolls = rollCount,
	level = levelNumber,
	guild = guildFlag, -- boolean the server already decided
	paid = paid, -- accepted and ignored
})
-- Paint shown.goals from the top left. At most 3. In this order.

local noted = StarterGoals.grant(state, "forge", progress)
-- Store noted.state only when noted.ok.
-- When noted.accepted, noted.keys == 10 and noted.payout is
-- { currency = "shardKeys", amount = 10, goal = "forge" }.
-- noted.goals is the window after the grant. The goal that just
-- appeared is not paid by this call.
```

The five ids, sentences, and goals are frozen:

| id | text | goal |
|---|---|---|
| `forge` | Craft your first item at the Forge | 1 |
| `rootvault` | Clear Rootvault | 1 |
| `rolls` | Roll 10 shards | 10 |
| `level` | Reach Lv 5 | 5 |
| `guild` | Join or browse a guild | 1 |

`CONFIG.shardKeys` is 10. `CONFIG.currency` is `"shardKeys"`. `CONFIG.visible` is 3. A count above the goal still pays 10, once. The painted `progress` caps at the goal, and `met` is true at or above it. Guild progress is 1 when the flag is true and 0 when it is false.

A `userId`, `UserId`, `playerId`, `PlayerId`, `guildId`, or `GuildId` field refuses the call. The result does not copy that field. A `productId`, `robux`, `cost`, or `skip` field refuses the call and grants nothing, including `robux = 0`, `cost = 0`, and `skip = false`. There is no free skip of these goals.

Suggested server calls, after this merges: a craft that is not a reroll, a Rootvault victory, a shard roll, a level-up, and the guild decision. Build `progress` on the server. Do not forward a client user id or guild id. Do not call this from `FirstSession`, `Onboarding`, `Loops`, or `LoopHud`. Do not bump Schema. `Loops.PREMIUM_ENABLED` stays false.

Suggested pay, in the same mutate as the save, only when `accepted == true`:

```lua
Economy.grant(data, noted.payout.currency, noted.payout.amount, "starter_goal")
```

`Economy.grant` does not cap the balance. Schema reconcile still caps `shardKeys` at 99999. This module does not call `Economy`.

## Questions

1. The level sentence is `"Reach Lv 5"`. The design line also says "(unlock talent)". Should the painted text stay `"Reach Lv 5"`, with no parenthetical?
2. The Rootvault sentence is `"Clear Rootvault"`. The minute-5 line says "Clear Rootvault (Normal)". Should any clear the server counts meet this, or only a Normal victory? The tutorial antechamber is not this module's count. Suggested: pass 1 for a `DungeonService` victory whose note is "Rootvault cleared.", and pass 0 for the antechamber.
3. Which number is `level`? Profile `level` is the account level, and `Progression` unlocks "Level 5 talent and daily quests" there. Class level comes from `Classes.progress`, and `Classes.TALENT_LEVEL` is also 5. This module compares the caller's number to 5 and does not read either field. Which one should the server pass?
4. Which count is `rolls`? Profile `shardRolls` is lifetime, and the tutorial already rolls once. This module does not subtract that roll. Should the server pass lifetime `shardRolls`, or a count that starts when this tracker opens?
5. What increments `forge`? The profile has `craftingXp`, not a craft count. The weekly `forge` quest is "Upgrade 3 pieces of gear", which is a different goal. `CraftService.craft` can be a reroll (`rerolled == true`). The tutorial's free ring is the first-session forge step, and this module does not load that module. Suggested: count one successful craft that is not a reroll, and do not count the tutorial ring. Is that the increment?
6. What sets the guild flag? The profile has no guild id. `guild == true` meets the goal. A `guildId` on the progress table is refused. Is the flag "joined a guild", or "opened the Guild Plaza once"? Who stores it?
7. Where should `{ returning, granted }` live? It is not in Schema. Schema stays 21. Suggested: add `starterGoals` on the next free version, `{ returning: boolean, granted: { forge, rootvault, rolls, level, guild } }`. Keep the counts derived. A browse flag may need its own boolean if nothing else remembers it. Until that wire, nothing in `src` should load this module.
8. Who is `returning`? `fresh({ returning = true })` shows no goals and pays nothing. This module does not read `onboardDone`. Passing `onboardDone` as `returning` would hide the tracker from everyone who finished the intro, so the after-minute-5 goals would never show. Suggested: a new profile stays `returning = false` after the intro, including a skip. Pass `returning = true` only when a saved `starterGoals` record was already closed, or when an account flag says this account already had the tracker. A second character is a new profile today. Suppressing that alt needs an account flag that does not exist. That is a Kevin call, same shape as the T-088 answer.
9. `grant` pays only a goal that is already in the three. A later goal that is already met stays unpaid until a grant reveals it. One call pays one goal and does not pay the goal that just appeared. Should a met goal pay while it is still hidden? Should the server, in one mutate, keep calling `grant` with the returned state until the front of the window is not met?
10. The Shard Key amount is the frozen placeholder 10, same for every goal, paid or free. Five grants is 50 keys. An Uncommon chest costs 40. Should 10 stay until Kevin picks a number? `paid` does not raise it. A `productId`, `robux`, `cost`, or `skip` field grants nothing.
11. The view's `progress` caps at the goal, so 100 rolls show 10, and `met` is still true. Should the tracker show the raw count instead?
12. Should the client paint by loading this module and calling `show`, or should the server send the three rows? The design wants the tracker at the top left. `LoopHud` still paints weeklies and was not edited. Suggested ledger reason is `"starter_goal"`. Is that the reason string, and is the top-left tracker a new widget?

## Answers from Ghost

3. Pass account `profile.level`.
