# T-096 hooks for GHOST

`Codex` is pure. It does not teach a fight, pulse a button, or grant keys, gold, a cosmetic, or a title. `paid` does not unlock an entry. A paid skip is refused. Nothing in `src` loads it yet.

`unlock(state, seen)` records entries the server has already seen. A `true` flag sticks. A later `false` does not lock it again. `lookup(state)` returns the unlocked pages, in table order, with `id` and `label` only. `hint(state, request)` returns one sentence, and only when `request.stuck` names that one entry, the entry is unlocked, and the entry has a sentence. Store `state` only when `ok == true`. There is nothing to pay. Each call returns a new table.

```lua
local opened = Codex.fresh()
-- opened.state.unlocked.attack == false

local noted = Codex.unlock(state, {
	attack = seenAttack, -- boolean the server already decided
	dodge = seenDodge,
	perfect = seenPerfect,
	skills = seenSkills,
	telegraphs = seenTelegraphs,
	shards = seenShards,
	doors = seenDoors,
	pets = seenPets,
	crafting = seenCrafting,
	rarity = seenRarity,
	paid = paid, -- accepted and ignored
})
-- Store noted.state only when noted.ok.
-- noted.discovered lists ids that flipped to true on this call, in table order.
-- noted.keys == 0 and noted.gold == 0. noted.payout is nil.
-- Do not grant a cosmetic or a title.

local shown = Codex.lookup(state)
-- Paint shown.entries when the player opens the Codex. No hint text.

local line = Codex.hint(state, { stuck = "attack" })
-- Show line.hint only when it is a string.
-- One entry. The caller already waited. Do not pass the elapsed time.
```

The ten ids and labels are frozen. Only two hints are frozen:

| id | label | hint |
|---|---|---|
| `attack` | Attack/combos | Keep swinging |
| `dodge` | Dodge | Dodge! |
| `perfect` | Perfect dodge | |
| `skills` | Skills | |
| `telegraphs` | Telegraph colors | |
| `shards` | Shards/sockets | |
| `doors` | Door choices | |
| `pets` | Pets | |
| `crafting` | Crafting | |
| `rarity` | Rarity colors | |

`CONFIG.keys` is 0. `CONFIG.gold` is 0. Ten discoveries still pay 0. `lookup` does not copy the hint onto the page, so opening the Codex does not nag. `hint` does not unlock. A locked entry, a missing `stuck`, and an entry with no sentence all return no sentence. Skills, telegraphs, shards, and crafting stay in that last group: a glow or an arrow, not Codex text.

A `userId`, `UserId`, `playerId`, `PlayerId`, `guildId`, or `GuildId` field refuses the call. The result does not copy that field. A `productId`, `robux`, `cost`, or `skip` field refuses the call and unlocks nothing, including `robux = 0`, `cost = 0`, and `skip = false`. There is no paid skip of a Codex entry. An unknown field, including `elapsed`, is refused. A missing seen flag is refused, and that call unlocks nothing.

Suggested server calls, after this merges: the moment the server decides a mechanic has been seen, then `lookup` when the menu asks, and `hint` after the caller has waited on that one mechanic. Build `seen` on the server from the saved record. Do not forward a client user id. Do not call this from `StarterGoals`, `FirstSession`, `Onboarding`, `OnboardingService`, `Loops`, or `LoopHud`. Do not bump Schema. `Loops.PREMIUM_ENABLED` stays false.

Do not call `Economy.grant` for a Codex unlock. `titles.md` is a separate catalog. This module does not grant one of those titles.

Loading-screen tips are G-020, in `docs/content/loading_tips.md`. This module does not read that file. Training Grove is the optional Haven course in the design. It is not an entry here.

## Questions

1. When does the server set a seen flag? `hint` returns a sentence only after that entry is already unlocked, so `"Keep swinging"` cannot show while `attack` is still false. The design's stuck line is for the teaching moment, before the player has succeeded. Suggested: set the flag when the moment starts (the saplings are there, the charger is winding up, the skill cluster is on screen), not when the player lands the input. Landing the hit stays a combat fact. If `seen` means they already did the mechanic, the stuck hint never fires during the moment it was written for. Needs Kevin.
2. Who keeps this across an alt? This module has no `returning` flag. `fresh()` starts locked. A saved record is the memory, and a new profile starts locked. All ten flags already refuse a second unlock, so finishing the list does not need a second switch. A second character is a new profile today. Suppressing that alt needs an account flag that does not exist. Needs Kevin, same call as T-088 and T-095.
3. How long is the stuck wait, and what cancels it? The design says about 8 seconds. This module does not read a clock, and a request that includes `elapsed` is refused. Suggested: the caller waits 8 seconds on the mechanic the player is in, then passes `stuck` for that one id. One timer. Leaving the moment clears it, and a second mechanic does not get a second line in the same call. Needs Kevin if 8 should be a different number, or if the timer should pause while the player is in a menu.
4. Where do the glow and the arrow live? `skills`, `telegraphs`, `shards`, and `crafting` have no sentence. The design's cues are a button glow, a color icon over the boss, a glow on the socket, and an arrow to the Forge. This module will not return those as Codex text. Suggested: Ghost paints them beside the fight or the Haven path, and does not add a sentence later. `perfect`, `doors`, `pets`, and `rarity` have neither a sentence nor a cue in this module.
5. The dodge cell in the design says `"Dodge!" icon pulses`. The frozen sentence is `"Dodge!"` and nothing after it. Suggested: Ghost pulses the dodge icon in the HUD and does not append words. The hint result is that one string.
6. Where should `{ unlocked }` live? It is not in Schema. Schema stays 21. Suggested: add `codex` on the next free version, `{ unlocked: { attack, dodge, perfect, skills, telegraphs, shards, doors, pets, crafting, rarity } }`. Keep the booleans stored. Do not fold this into `Onboarding.starter`, `FirstSession`, or `StarterGoals`. Nothing in `src` loads this module until that wire. Pass the profile's saved state, never a client state. Save the returned state only when `ok == true`. A failed call keeps the previous save. Do not apply two unlock results that both started from the same old state.
7. Where does the page sit in the menu? `UiRouter.TABS` is `hero`, `bag`, `pets`, `roll`, `raids`, `market`, `pass`, and `settings`. There is no Codex tab. This row does not edit `UiRouter` or `Keybinds`. Suggested: the server calls `lookup` and `hint` and sends the rows. The client paints them and does not call `unlock`. A new tab waits for a row that names those files. The page does not open itself, and a hint does not pause the game. There is no `blocked` flag and no force-read flag.
8. Should locked entries show as blanks? `lookup` returns only unlocked pages, in table order, so the menu does not list mechanics the player has not seen. Suggested: keep it that way. Needs Kevin only if the Codex should show locked silhouettes.
9. Should a later call take one new id instead of the full map? Suggested: keep the ten booleans. A missing key refuses the call and unlocks nothing, so a partial payload cannot look like a fresh Codex. The module ORs `seen` into `unlocked`. `paid = true` still records a seen entry and does not record an unseen one. Only `productId`, `robux`, `cost`, and `skip` refuse the call.
