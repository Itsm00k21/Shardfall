# T-044 hooks

Wired `RaidPremade` into `RaidService.post`, `RaidService.join`, and `RaidService.board`. `RaidPremade.luau` was not edited. No new remote. `RaidPost` and `RaidJoin` already take a token in `Remotes` (`capacity` 3, `perSecond` 0.5). The service does not take a second token.

The live `RaidPost` call is still `(tag, difficulty)`. A string tag is one tag. A table in that first argument is the new payload (`difficulty`, `tags` or `tag`, `partySize`, `slots`, `role`, `requiredClears`, `gearScore`, `title`, `guided`). `RaidJoin` still takes one argument. A positive integer is the id and the role is flex. A table reads `id` or `listingId`, and `role`. Anything else on that table is ignored.

The server stamps `hostUserId`, `createdAt`, and `members`. Client `members`, `hostUserId`, `createdAt`, `expiresAt`, `closed`, `now`, `clears`, and `userId` are not copied. `guided` is copied when the client sent it, so a guided request is refused instead of stored as a normal row. `os.time()` is the clock. Titles go through `TextService:FilterStringAsync` and `GetNonChatStringForBroadcastAsync` and stay on the wrapper. A blank title skips the filter. The current Board button sends no title, so it does not need the filter.

`RaidService.memberLeft(player)` runs `depart`. `Players.PlayerRemoving` in this module calls the same function. A second call is safe.

## Answers

1. The deadline second stays closed. `now >= createdAt + listingSeconds` is expired. The server does not reopen that second.
2. Flex keeps the module's rule. A flex player takes the first open slot in the host's list.
3. A tank, healer, or DPS may sit in a flex slot after their own slots are full. The server does not add a second rule.
4. A party of four DPS can be posted. Finder's tank and healer minimums are not applied on post or on join.
5. Join does not compare `gearScore`. Hard and Shardbreaker may store a non-negative integer. Story and Normal still refuse the field, including 0. The plaza copy omits `gearScore` so a stored number is not shown as a filter. A missing score is not treated as 0, because nothing compares it.
6. A missing `requiredClears` is 0. `1.5` is refused, not floored. The exact count may join. The host must meet the number too. Until `raidClears` exists, a requirement above 0 accepts nobody, and the host cannot post it. A corrupt stored count is unusable. Nil is 0.
7. Any seat in an active listing blocks a new post and blocks joining a second listing. The module still allows a seated player to host. The server does not.
8. The cap is 20 active rows. A full board refuses the new post. Expired and closed rows are removed and do not count. The oldest row is not dropped. A restart clears the board.
9. A host leave closes the row and keeps the other members on the record. The plaza removes the row as soon as it is not active. A non-host leave frees that slot and leaves the row up.
10. Title cap is 48 bytes, in `RaidService`, because `RaidPremade.CONFIG` was not given a cap. Over the cap, a control character, a non-string, or a failed filter refuses the post. The raw title is never stored.
11. `guided == true` and difficulty `"guided"` both refuse. The server passes a client `guided` flag through so it cannot be stripped into a normal listing.
12. The count is `profile.raidClears` when that field exists. This path does not read `raidFinderCooldownUntil`. It is the total count, not per difficulty, until a per-difficulty field exists.
13. `RaidFinder` `roleTargets[8]` stays 1 tank, 1 healer, and 6 DPS. This wire does not call `RaidFinder` or `RaidFinder.form`.
14. A full listing does not launch. There is no ready check yet, so Story, Normal, Hard, and Shardbreaker all wait. Hard and Shardbreaker cannot use `Raids.difficulty` or `DungeonService.enter`. Post and join still call `Raids.roleOk`. Level uses the Story row's level (15). Normal, Hard, and Shardbreaker also require `raidStory`. There is no Hard-clear flag, so Shardbreaker does not require a Hard clear yet. A missing role on the old Board button is flex. The last seat of a Story or Normal listing backfills only when that host is already in a matching pull. It does not call `queue`.

## Follow-ups

- `DungeonService` should call `RaidService.memberLeft` from its `PlayerRemoving` path. This module already does, and a second call is safe. `DungeonService.luau` was left alone.
- There is no leave button. A seated player stays until they disconnect or the row expires. A leave remote was not added.
- Titles that fail `TextService` are refused, including in Studio. The Board button has no title, so that click still posts.
- `gearScore` is stored and not enforced. Showing it as a requirement would be a lie.
- The Board button now requires the Heartwood level. A level 1 character gets "Level 15 opens The Heartwood."
