# Save and migrate risk review

G-057. Data-loss and migrate gaps in `DataService.luau`, `Schema.luau`, `ProfileLoad.luau`, and `SessionLock.luau`. This file does not change code.

A normal leave writes the memory profile and clears the lock (`DataService.luau:614-623`, `SessionLock.luau:119-125`). A string or a NaN `schemaVersion` returns `"corrupt"` and the claim returns nil, so the key stays as it was (`Schema.luau:789-790`, `ProfileLoad.luau:132-135`). A `schemaVersion` above 26 returns `"newer"` and is the same kind of refusal (`Schema.luau:792-793`).

Choice: a missing DataStore key should follow `Schema.template()` (`onboardDone` false, `onboardStep` `"open"`, `firstSession.returning` false). Confirmed on `81c60d8` and fixed in T-208: `Schema.migrate(nil)` returns that template, and a stored `schemaVersion` below 14 still stays `onboardDone` true. S2 was confirmed on the same tip and fixed in T-210: a table with no `schemaVersion` keeps gems, companions, raid marks, codex, and `lastSeen` that are already present, so `applyReturn` can pay the welcome chest. A stored version below a step still receives that step's defaults. S3 was confirmed on the same tip and fixed in T-209: autosave and `release` do not write a profile that is still loading or ephemeral, so a late timeout cannot store the memory fallback over the claimed save. S5 was confirmed on the same tip and fixed in T-211: a bag, pet list, or materials value that is present and not a table is `"corrupt"`. The load does not claim, and `reconcile` does not replace that field with an empty table. S4 was confirmed on `4891074` and fixed in T-212: a failed persistent load releases a lock this server owns and leaves the stored profile in place. S6 was confirmed on that tip and fixed in T-214: a foreign `lockedAt` of NaN or infinity is expired, and the owner job stays owned. S7 was confirmed and fixed in T-215: positive infinity in a wallet becomes 0. S10 was confirmed and fixed in T-216: `mutate` restores its backup only when no later mutate has started. S11 was confirmed and fixed in T-213: shutdown sets its flag before spawning releases, autosave does not start a write after that, and `release` does not keep waiting on a teleport. The 30 second budget still ends a release that is already inside `UpdateAsync`, because `BindToClose` cannot outlast the engine. S12 was confirmed and fixed in T-217: a final save that returns `"missing"` warns. S8 stays open: the accepted loss is one 60 second autosave gap, and shortening the 20 minute timeout would let another server take a live profile during an outage. S9 stays open: the two saves are sequential, and a crash between those commits cannot run the undo.
